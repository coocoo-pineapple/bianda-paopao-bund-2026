## 优先级已重排（08-07 修订）

原顺序是「联机 → AI → 材料」。**改成「壳系统 → AI → 联机」**，理由：

| | 壳系统 | 联机 |
|---|---|---|
| 工作量 | 半天 | 原设计一天+，**瘦身后 2-3 小时** |
| 视频里能不能讲清 | **3 秒，不用一个字** | 要开两个窗口，评委可能没注意到 |
| 创意分 | **最高** | 中（工程分，不是创意分） |
| 做不完的后果 | 产品没记忆点，泯然众人 | 少一个「实时」标签，不致命 |

**创意分性价比差了一个量级。** 联机保留，但排到 AI 后面，且方案瘦身。

### 联机方案瘦身

砍掉 SQLite 落库和完整权威状态机，改成**内存中继**：

- 服务端内存里存一份泡泡表，跑同样的衰减，每 3 秒广播一次热度快照
- 吹气/戳破/发帖是事件转发
- **重启丢数据 —— 接受。** demo 场景下没人会连续跑三天
- 依赖从 3 个降到 2 个（去掉 `better-sqlite3`），代码从 ~600 行降到 ~200 行
