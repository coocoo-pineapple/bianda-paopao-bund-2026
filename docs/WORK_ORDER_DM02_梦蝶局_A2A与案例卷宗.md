## 为什么要做这两件事

**1. 现在的对局，AI 是自导自演。**
`adEngine()` 一次 `/api/ask` 就把四个角色的台词全生成了——一个模型同时知道所有人的底牌，再"表演"互相试探。**逻辑上，撒谎的人和识破的人是同一个脑子。**这在评委面前是经不起追问的：「你们这算多智能体吗？」目前答案是不算。

**2. 玩完一局，东西没留住。**
破绽只进了 `S.lib` 几条散装文字。而梦蝶局对人最大的价值恰恰是——**职场的坑，先在这儿摔一遍**。摔完得留下地图给后面的人。

## 目标 A · 视野隔离（A2A 方向的最小落地）

**每个座位是一个独立智能体，只知道自己的身份 + 台面上公开说过的话。**

- 一轮 = 四次**各自独立**的 `/api/ask`，四个 `system` 互不包含对方的底牌
- 撒谎者的 system 里有"你的真实动机是 X，不要承认"；其他三个的 system 里**没有这句**
- 每个 agent 的输入只有：自己的身份卡 + 公开台词历史 + 玩家打出的质询牌（如果指向它）
- 一局三轮 = **十二次独立调用**，这个数字能在 W1 的调用记录面板里数出来——**这是最便宜的技术深度证据，比任何说辞都硬**

**这不需要改服务端。**现有 `/api/ask` 就能做，只是从"发一次"变成"发四次、system 各不相同"。

配套的 **Agent Card**（每个座位一张，组局时可见）：身份名 / 专长 / 人格摘要 / **对局战绩**（骗过几人 · 被识破几次 · 识破他人几次）。战绩跟着分身走进技能集市——**这就是它的简历，也是"AI 分身凭什么值 99 元"的答案**。

**留给 Codex 的两个问题**（写进 BLACKBOARD，别自己动 `server/`）：
1. `ai.gate` 的限流阈值是多少？同一轮并发四个请求会不会被拦？被拦就是降级，**降级要照实标注，不许改成串行假装成功**
2. 四并发的延迟能不能接受？不能就每轮内串行、轮间不等

**降级契约不变**：任何一个座位调用失败 → 该座位走 `adScriptGen()` 并标「脚本模拟 · 未调用模型」。**允许一局里三个真一个假，逐座位标注，不要整局一刀切。**

## 目标 B · 案例卷宗

**一局结束，自动生成一份卷宗**，结构固定：

```
场景 · 四个身份 · 谁在撒谎 · 关键破绽（最多三条，带原话）· 一句教训
```

要求：

- 卷宗**是一颗泡泡**——存进资讯库后能被吹大、能沉底、能被后来的人翻到、能在集市标价。**别做成孤立的存档页**
- 提供一个**卷宗架**入口（复用现有窗口系统，别另起一套 UI），能翻看历史卷宗，附几份预置的"经典案例"当种子
- 输了也生成卷宗。「玩过的局，不白玩」的落点在这里

一句话记住定位：**一个人踩过的坑，变成所有人的地图。**

## 验收

1. Playwright 跑一局，抓网络请求：**一轮四次 `/api/ask`，四个 `system` 内容互不相同**，撒谎者的动机只出现在它自己那次里
2. 断网重跑：逐座位降级标注，不整局一刀切，界面不假装成功
3. 组局界面能看到每个座位的 Agent Card 含战绩；打完一局战绩有变化
4. 一局结束生成卷宗并进资讯库，能在卷宗架翻到，**能被吹大**
5. `pageerror` / console error / 4xx 全为 0；`node tools/build-dist.js` 过 `$$` 自检
6. 三个新状态（组局 / 三轮质询中 / 卷宗）各截一图

**优先级**：时间不够就砍 —— **视野隔离 > 卷宗 > Agent Card 战绩 > 卷宗架 UI**。第一项是"算不算多智能体"的分水岭，独一份不可砍。
