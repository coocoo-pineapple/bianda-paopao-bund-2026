> 目标形态：**联网多人实时**，评委点开链接就能和别人吹同一片水面。

## 零、这份架构的唯一约束

**2 天。** 所有决策都由这一条推导出来。凡是"更正确但更慢"的方案一律不选。

三条铁律：

1. **不重写。** `变大泡泡-原型.html`（1192 行，7 个模块全部跑通）是最大资产，不是草稿。整个架构是**给它包一层壳**，不是拿它当参考重做。
2. **一个进程。** 一个 Node 服务同时干四件事：托管静态页、WebSocket 广播、SQLite 落库、调 AI。不拆微服务，不上 Redis，不上消息队列。
3. **每一步都能单独交付。** 任何时刻停工，手上都有一个能提交的版本。第一天结束若后端崩了，退回单文件 HTML 仍可提交。

## 二、最关键的一个决策：只同步热度，不同步坐标

这是整个架构的支点，省掉的复杂度最多。

原型里每个泡泡对象混着两类字段：

| 类别 | 字段 | 归谁 |
|---|---|---|
| **内容与生命** | `id text type kind author ind co heat pokes manHeat botHeat peak` | **服务端权威** |
| **视觉与物理** | `x y vx vy r el hover out dead` | **客户端本地，永不上行** |

**每个人看到的水面，泡泡飘的位置可以不一样，但大小、生死、内容必须一样。**

为什么这样对：
- 泡泡是布朗运动式的自由漂浮，本来就没有"正确位置"。同步坐标要处理插值、抖动、时钟漂移——那是三天的活。
- 而"我吹了一口，别人屏幕上那个泡泡当场变大"——这才是评委要看到的联机感，它只需要同步 `heat`。
- 带宽从每秒几十 KB 降到每次操作几十字节。

**实现代价：改动集中在 4 个函数**（`mk` / `blow` / `pop` / `sink`），物理循环 `step()` 一行不动。

### 权威循环怎么跑

衰减和生死判定从客户端 `step()` 移到服务端：

```
服务端每 1s tick：
  每个泡泡 heat -= 0.06 * 60          // 与原型 decay 手感对齐
  heat >= 55  → burst()  广播 burst 事件 + 三个子泡泡的 mk 事件
  heat <= 0.6 → sink()   广播 sink 事件（biz/news 进 lib，其余进 sunk）
  每 5s 广播一次全量 heat 快照（对齐用，防漂移）
```

客户端收到 `heat` 更新后，只做一件事：`b.heat = 新值`。原有的 `rOf(b.heat)` 插值、浮力、`.tense` 濒爆样式**全部自动跟着变，一行不改**。这就是不重写的收益。

### 持久化降级（08-07 修订）

优先级重排后（壳系统 > AI > 联机），联机预算从一天压到 2-3 小时。砍掉落库：

- 泡泡表活在**服务端内存**里，重启丢数据 —— **demo 场景下接受**，没人会连续跑三天
- 依赖从 3 个降到 2 个（去掉 `better-sqlite3`），联机代码从 ~600 行降到 ~200 行
- 唯一需要跨会话保留的是**用户 token 和马甲**，存在浏览器 `localStorage`，服务端不存

下面的表结构**赛后再用**，现在照着它设计内存里的对象形状即可，字段名保持一致，将来接库是平移。

```sql
CREATE TABLE users (
  token      TEXT PRIMARY KEY,   -- 浏览器 localStorage 生成，零注册
  alias      TEXT,               -- 马甲花名
  ind        TEXT,               -- 行业（互联网/金融/…）
  level      TEXT,               -- 粗职级（P7/三年/…）
  bot_conf   TEXT,               -- 用户机器人配置 JSON
  last_seen  INTEGER
);
CREATE TABLE bubbles (
  id INTEGER PRIMARY KEY, text TEXT, type TEXT, kind TEXT,
  author TEXT, ind TEXT, co TEXT,
  heat REAL, man_heat REAL, bot_heat REAL, peak REAL, pokes INTEGER,
  state TEXT,          -- alive | burst | sunk | popped
  born INTEGER
);
CREATE TABLE harvest (      -- 用户机器人收菜箱
  id INTEGER PRIMARY KEY, token TEXT, kind TEXT,
  title TEXT, body TEXT, taken INTEGER DEFAULT 0, t INTEGER
);
CREATE TABLE lib (          -- 行业资讯库（由 biz 类泡泡沉淀）
  id INTEGER PRIMARY KEY, text TEXT, ind TEXT, peak REAL, t INTEGER
);
```

### 匿名身份：零注册

评委没有耐心注册。首次打开：

1. 前端 `localStorage` 无 token → `POST /api/enter` → 服务端发一个 token + 随机马甲（沿用原型的 `ALIASES` / `IND_POOL`）
2. 之后每次连 WS 带上 token
3. 粗粒度标签「互联网 · P7」跟着泡泡走——够判断可信度，不够定位到人（产品思考文档推论二）

**「我司」筛选档设人数门槛**：同 `co` 在线不足 5 人时该档灰掉并提示。这条是产品思考里明确要求的，不能漏。

### WebSocket 协议

十条消息，够了。

```
上行（客户端 → 服务端）
  {t:'enter',  token}
  {t:'blow',   id, n}
  {t:'poke',   id}
  {t:'post',   text, type, ind}
  {t:'ask',    bot, q}          // 博主机器人提问
  {t:'dream',  action}          // 梦蝶局：开局/押注/再来
  {t:'harvest'}                 // 收菜

下行（服务端 → 客户端）
  {t:'init',   bubbles[], me, lib[], sunk[]}
  {t:'heat',   [[id,heat,manHeat],…]}   // 每 5s 全量对齐
  {t:'mk',     bubble}
  {t:'gone',   id, why:'burst'|'sink'|'poke', kids?[]}
  {t:'ai',     channel, chunk}          // AI 流式回包
```

## 四、AI 层：这次的技术分主要在这

这是 AI 作品，**脚本模拟的假 AI 会被一眼看穿**。三个用途接真模型，各自有降级路径。

| 用途 | 做什么 | 降级（无 key / 超时 / 报错） |
|---|---|---|
| **梦蝶局** | 4 个 Agent 各持虚构身份自主对局，互相试探，用真实职场诈骗话术；揭底时逐句标破绽 | 回落到原型内置的 2 局静态剧本，界面角标改为「脚本模拟」 |
| **博主机器人** | 四段式（人格 DNA / 框架库 / 固定动作流程 / 禁区）拼成 system prompt，真回答用户提问 | 回落到关键词匹配的内置答案 |
| **用户机器人收菜** | 按用户设定的采集范围，定时产出情报条目进收菜箱；也会自主吹别人的泡泡 | 从种子池抽条目 |

### 三条设计红线

**一、梦蝶局要真多 Agent，不能一个模型演四个人。**
四次独立调用，每个 Agent 只拿到自己的身份和已公开的对话，**看不到别人的底牌**。这是"互骗"能成立的前提，也是评委一问就会问到的地方。一个 prompt 生成整段剧本的做法，追问两句就露馅。

**二、机器人吹的气不进「今日最大泡」评选。**
`manHeat` / `botHeat` 在服务端分开累加，最大泡只认 `manHeat`。产品思考里标死了：这条不做，热度体系从根上崩掉。

**三、AI 调用全部走服务端，key 绝不出现在前端。**
且每个 token 有速率上限（梦蝶局 5 次/小时，博主问答 20 次/小时）。评委的链接是公开的，不设限一晚上能烧掉几百块。

### 降级不是遮丑，是加分项

界面上明确标注当前是「真实模型」还是「脚本模拟」。产品思考文档里的诚实约束（DNA 第 4 条：反虚假便利）在这里正好变成技术可信度——**评委看到你敢标"这段是模拟的"，反而更信你标"这段是真的"**。

## 六、部署

线上提交，评委随时可能点开，所以要一个**稳定可访问的公网地址**。

### 已定：香港轻量服务器（阿里云 / 腾讯云）

选它的唯一理由：**免备案，且能绑域名上 HTTPS。**

大陆机房要备案，备案 7-20 个工作日，到 8.9 下不来。没备案就只能走 `http://IP:3000` 裸地址，后果不只是难看：

- 大陆机房 80/443 对未备案域名是封的
- 无 HTTPS，浏览器标「不安全」
- **裸 IP + 非标端口在微信里很可能打不开** —— 评委多半是从微信点进来的，这条致命
- 一个「匿名职场社区」配一个像钓鱼站的链接，观感自伤

香港节点大陆访问 50-80ms。这个产品没有大流量、没有视频，够用。

### 部署清单

| # | 事 | 备注 |
|---|---|---|
| 1 | 香港轻量，最低配即可（1C2G） | 单 Node 进程，吃不了多少 |
| 2 | 域名解析到公网 IP | 免备案，直接生效 |
| 3 | Caddy 反代 3000 端口 | **Caddy 自动签 HTTPS 证书**，比 Nginx 少一半配置 |
| 4 | `pm2` 守护 Node 进程 | 崩了自动拉起 |
| 5 | 安全组只开 22 / 80 / 443 | 3000 端口不对外 |

### 三条运维红线

- **API key 走服务器环境变量**，不进代码仓库、不进前端
- **每日额度熔断**，超了自动降级到脚本。公开链接不设限，一晚上能烧掉几百块
- **比赛期间不碰生产**。8-08 深夜冻结后只看不改

### 兜底

**无论如何都要导出一份纯单机 `app.html`** —— 双击打开、零网络、全功能（脚本模拟）。作为提交附件一并交上去。

**服务器挂了不至于零分，这是唯一的保险。**

## 七、风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| **同步改造把泡泡手感改坏** | 致命，核心爽感没了 | 改造只碰 4 个函数，物理参数（`rOf`/`BURST`/浮力/`POKE_NEED`）一个不碰。改完先自己连点 10 分钟 |
| AI 调用慢，梦蝶局播放卡顿 | 演示效果差 | 流式返回；开局前预生成前 4 行；界面用打字机效果掩盖延迟 |
| 评委同时点开，服务被打爆 | 现场翻车 | 单进程能扛几十并发足够；tick 广播做合并；设连接数上限 |
| API key 被刷爆 | 花钱 + 服务不可用 | 服务端限流 + 每日总额熔断，超了自动降级到脚本 |
| **2 天不够** | 交不出 | 每天结束都有可提交版本；砍功能不砍质量 |

## 八、三句话总结

1. **不重写原型，只给它包一层同步壳** —— 改动面锁死在 1 个新文件 + 4 个函数。
2. **只同步热度和生死，不同步坐标** —— 联机感全拿到，复杂度砍掉九成。
3. **AI 必须是真的，降级必须是标明的** —— 前者拿技术分，后者拿可信度。
