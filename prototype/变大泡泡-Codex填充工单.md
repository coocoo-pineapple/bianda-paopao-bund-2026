## 0. 先读这段（公共约束）

**产品是什么**：《变大泡泡》——伪装成 Word 述职报告的职场摸鱼社区。每条八卦是一个泡泡，点一下 = 吹一口气，泡泡变大、浮得更高、活得更久，吹爆了炸成衍生话题。品牌内核是庄周，标语「子非鱼，安知鱼之乐」。

**已经写好、不要动的部分**：Word 外壳、六个选项卡、泡泡物理引擎、老板键三态（社区 / 述职报告 / Windows 桌面）、拼豆网格、情报投放、运营后台的控温与注气。

**你要做的**：把页面上带 `class="stub"` 的虚线框，替换成真能交互的内容。一次做一个模块，做完自测再做下一个。

**可以直接调用的现成函数（文件末尾 HOOKS 注释里也有）**：
```js
mk(text, type, heat, kind, author)  // 新建泡泡并入场
   // type ∈ 'salary'|'layoff'|'boss'|'peer'|'biz'|'fun'
   // kind ∈ 'user'|'bot'|'brand'|'job'|'news'（非 user 会自动带虚线边框和角标）
blow(b, n)      // 给泡泡 b 吹 n 口气，会自动触发爆泡判定
burst(b)        // 直接引爆
pop(b, 'poke')  // 戳破
sync()          // 刷新右栏所有面板。改完任何数据都要调一次
go('home'|'insert'|'draw'|'ref'|'review'|'ops')  // 切页
esc(str)        // HTML 转义，拼 innerHTML 时必须用
S.bubbles / S.sunk / S.hall / S.arb   // 在场 / 已沉 / 名人堂 / 仲裁队列
RIBBONS         // 每页顶部功能区的 HTML，切页时自动注入
```

**样式约束（严格遵守，否则风格会崩）**：
- 只用文件顶部 `:root` 里已有的 CSS 变量，不要引入新配色
- 复用已有类：`.card` / `.card h4` / `.card .bd` / `.rbtn` / `.rbtn.pri` / `.ta` / `.muted` / `.chip` / `.pick` / `.grid2` / `.grid3` / `.cmt` / `.hot`
- **全站禁用 emoji**。禁用渐变（泡泡本身的径向高光除外）。禁用圆角 > 4px 的卡片
- 整页要看起来像一份安静的 Word 文档，**泡泡是唯一会动的东西**。你新加的东西不许有花哨动画
- 中文正文用 `var(--serif)`（宋体），UI 用默认无衬线

**诚实约束**：全部是假数据。凡是模拟出来的东西（机器人回复、抓取、剧本），界面上要能看出来是演示，不许伪装成真实调用。

## 任务 1 · 梦蝶局（机器人身份局）

**位置**：`#v-review` 里「梦蝶局」那张 card 的 `.stub`

**是什么**：每个机器人抽一个虚构身份，在群里互相试探、互相「骗」。用户看戏 + 押注谁是骗子，播完揭底。名字出自庄周梦蝶——不知谁是谁。

**它不只是好玩**：剧本里的话术要用职场里真实存在的那几种（假猎头、假内推、假投资、假 HR 背调），所以这一局同时是**反诈演示**。揭底时要点出"这句话是破绽"。

**要做到**：
1. 内置 **2 局剧本**，每局 10–14 行对白。角色 4 个：Codex / 小龙虾 / 菠萝 / 如镜，各领一个虚构身份（如「猎头 Anna」「前同事老王」「HR 小林」「做投资的表哥」）
2. 点「开局」后逐行播放，每行间隔 900ms 左右，用 `.cmt` 样式渲染，自动滚到底
3. 播到一半出现押注区：4 个按钮选谁是骗子，选完继续播
4. 播完揭底：亮出真正的骗子、押中与否、并**逐条标出剧本里哪几句是典型话术**（用 `.muted` 小字挂在对应行下面）
5. 「再来一局」切换到另一个剧本

**数据结构建议**：
```js
const DREAM_PLAYS = [{
  title:'内推的那位',
  cast:{ 'Codex':'猎头 Anna', '小龙虾':'前同事老王', '菠萝':'HR 小林', '如镜':'表哥' },
  liar:'Codex',
  lines:[ {who:'Codex', tx:'...', tell:'典型话术：先给你一个远超市场价的数字'} , ... ]
}, { ... }]
```
`tell` 有值的行在揭底时才显示破绽注释。

**验收**：能完整播完一局、能押注、能揭底、能重开；两局剧本内容不同；揭底后至少标出 3 条破绽。

## 任务 2 · 博主机器人工坊

**位置**：`#v-review` 右栏「机器人工坊」那张 card 的 `.stub`（内容多的话可以在 `#v-review` 底部另起一个 `.card` 全宽放）

**是什么**：职场博主把自己的经验蒸馏成一个机器人，挂到社区替自己答疑。**传授经验的不一定是人。**

**四段式结构（这是重点，不许改成别的形状）**：
| 段 | 填什么 | 为什么 |
|---|---|---|
| 人格 DNA | 3–5 条不可妥协的判断 | 只能从博主本人蒸馏，这是机器学不来的部分 |
| 框架库 | 2–3 个专业方法 | 补提问者的短板 |
| 固定动作流程 | 每次回答的固定顺序 | 写死，防止套壳自由发挥 |
| 禁区 | 不聊什么、不承诺什么 | 划边界 |

**要做到**：
1. 左边表单四个 `textarea`（用 `.ta`），预填一个样例博主（建议「十年 HRD」）
2. 右边**实时预览**：给定一个样例提问（如「领导让我周末加班，我该不该拒绝」），根据当前四段内容拼出这个机器人会怎么回答
3. **关键：改动左边任何一段，右边预览必须同步变**。预览不需要真智能——按「固定动作流程」逐步拼装，每步引用一条对应的 DNA / 框架，把结构可视化出来就够了。让人看懂"人格是怎么决定回答的"
4. 底部一行商业说明：免费 3 问 → 深度咨询付费 → 社区抽成（这是博主愿意来的唯一理由）
5. 右栏已有的 3 个内置博主机器人（十年 HRD / 外企转国企的人 / 被裁两次的产品）要能点开提问，各配 4–6 条按关键词匹配的回答

**验收**：改 DNA 第一条，右侧预览的对应句子跟着变；3 个内置机器人都能问出不同风格的答案。

## 任务 3 · 捡手机文学

**位置**：`#v-ref` 里「捡手机文学」card 的 `.stub`

**是什么**：「你在会议室捡到一部手机。」逐条点开聊天记录，剧情自己长出来。**核心快感是窥视 + 逐渐拼出真相。**

**要做到**：
1. **2 部手机**，各 12–16 条消息。做成手机聊天界面的极简版（左右气泡、时间戳、对方昵称），但**配色继续用 Word 那套**，不要做成微信绿
2. 点「下一条」出一条，不能一次全给。节奏就是内容
3. 每部手机要有**转折**：前 5 条像普通同事闲聊，中段透出异常，最后 2 条反转
4. 读完出现「转成泡泡」按钮 → 调 `mk(摘要文本, 'peer', 12, 'news', '捡到的手机')`
5. 顶部一行免责：`这是虚构故事，如有雷同纯属巧合`

**内容方向建议**（选 2 个）：会议室捡到 HR 的手机 / 前台捡到实习生的手机 / 打印机上忘拿的一沓纸 / 共享文档里没删干净的批注

**验收**：两部手机都能逐条读完、都有反转、都能转成泡泡。

## 任务 4 · 爽文背单词

**位置**：`#v-ref` 里「爽文背单词」card 的 `.stub`

**是什么**：每个职场英语词配一句离谱的爽文例句。**荒诞是功能——荒诞才记得住。**

**要做到**：
1. **30 个职场高频词**（redundant / severance / headcount / attrition / probation / escalate / align / bandwidth / leverage / synergy / pipeline / churn / onboarding / offboarding / KPI / OKR / stakeholder / deliverable / bottleneck / scope creep …）
2. 每词一条爽文例句，中英混排，语气要足够离谱。参考调子：
   > 他冷笑一声：「**redundant**（冗余的）？」全场死寂。三年前被他们裁掉的那个人，今天坐在了对面的谈判桌主位。
3. 大字展示当前词 + 释义 + 例句（例句用 `var(--serif)` 宋体，视觉上像正文）
4. 「下一章」换词，「认识」「不认识」两个按钮 —— 不认识的词进复习队列，走完一轮后重出
5. 右上角挂一个 **装逼值** 计数器，每认识一个 +1，用 `.muted` 小字标「今日装逼值」
6. 走完 30 个出一句结算文案

**验收**：能连点走完一轮、不认识的词会重出、装逼值会涨。

## 任务 5 · 真学习区

**位置**：`#v-ref` 里「真学习区」card 的 `.stub`

**这一区是整个产品的立身之本**：摸鱼是入口，真东西是留存。**它要故意保持安静**——不做泡泡化、不做热度排序、不做点赞。摸鱼区越吵，这里越静，对比就是态度。

**要做到**：
1. **3 篇职场经验长文**，每篇 600–900 字，用 `var(--serif)` 宋体、`line-height:2.0` 排版，看起来就是 Word 正文
   - 第一篇全文展开，后两篇折叠（点标题展开）
   - 选题方向：怎么读懂 HR 的话术 / 被裁之后前 30 天怎么走 / 怎么跟一个不喜欢你的领导共事
   - **写法要求：不许写成鸡汤和方法论清单。要有具体场景、具体对话、具体数字，敢承认哪些做法没用。**（这是全产品唯一严肃的地方，写崩了整个产品的可信度就没了）
2. 每篇末尾一行作者署名 + 「这篇有用 / 没用」二选一反馈（只记数，不排序、不公开）
3. **学习打卡**：连续天数、今日 15 分钟进度条（`localStorage` 存），进度条用 `--word-blue` 实心，不要动画
4. 区块顶部一句题词：`无用之用，方为大用`，用 `var(--serif)`、`--ink-3` 小字

**验收**：三篇都能展开读完；打卡状态刷新页面后还在；这一区里找不到任何热度 / 排名 / 点赞元素。

## 任务 7 · 运营后台补完

**位置**：`#v-ops` 右下「待填充」card

**原则（重要）**：这个后台的每一个控件都必须挂着一条**留存或收入**。加控件的时候要在界面上写清楚它对应哪条。不许加"看起来很专业但没用"的按钮。

**要做到**：
1. **种子泡泡定时释放**：一个话题池（15 条）+ 释放间隔滑块 + 开关。开着的时候按间隔自动 `mk()` 投放，界面显示"下一条 XX 秒后"
2. **机器人排班表**：4 个机器人 × 发帖频率（低/中/高）× 时段（上午/午休/下午/下班前）。改完立刻生效——按频率定时让对应机器人 `mk(..., 'bot', 作者名)`
3. **博主机器人上架审核**：3 条待审申请（博主名 / 领域 / 提交的 DNA 摘要），通过 / 驳回。通过后加进 `#v-review` 的博主列表。旁边标「收入线三：抽成 30%」
4. 三个模块各用一张 `.card`，标题里直接写清对应哪条收入或留存

**验收**：种子开关打开后广场真的会自动冒新泡泡；改机器人频率后发帖节奏变化；审核通过后博主列表多一条。
